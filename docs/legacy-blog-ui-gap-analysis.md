# 旧博客路由 UI 交互分析与补充计划

## 1. 输入与范围

- 输入来源：`docs/ui.md`
- 分析范围：博客前台路由与页面交互（不含后台管理端）

## 2. 旧博客路由与页面 UI 交互描述

根据 `docs/ui.md`，旧博客核心交互可以整理为以下 5 类：

| 路由/入口   | 页面定位      | 关键 UI 交互                                                              |
| ----------- | ------------- | ------------------------------------------------------------------------- |
| `/my-blog/` | 主页          | 展示文章卡片流，点击文章进入详情页                                        |
| Header 导航 | 全局导航      | 点击「隧道」进入归档页；点击「分类」进入分类页；点击「标签」进入标签页    |
| 文章卡片    | 列表到详情    | 点击文章卡片跳转到文章详情页（示例路径为年月日+标题 slug 结构）           |
| 分类入口    | 分类聚合/筛选 | 点击分类 tab 或分类链接，跳转到指定分类详情（示例：`/categories/:slug/`） |
| 标签入口    | 标签聚合/筛选 | 点击标签 tab 或标签链接，跳转到指定标签详情（示例：`/tags/:slug/`）       |

补充说明：

- 旧站文章详情 URL 风格偏向内容型永久链接（`/my-blog/YYYY/MM/DD/:slug/`），而不是单纯的 `/post/:slug`。
- 旧站分类、标签都强调“可点击后进入对应 slug 详情”的交互闭环。

## 3. 当前项目对照分析（已实现 vs 缺失）

### 3.1 已实现交互

1. 已有首页、归档、分类、标签、详情路由，且 Header 默认导航项与旧站一致（隧道/分类/标签）。
2. 首页文章卡片可点击进入详情页，归档列表也可点击进入详情页。
3. 已有搜索页、主题切换等扩展能力（属于旧文档之外的增强项）。

### 3.2 主要缺失/偏差（按优先级）

1. 缺少旧链接兼容能力（高优先级）

- 旧站存在 `/my-blog/...` 前缀与 `YYYY/MM/DD/:slug` 详情路径。
- 当前仅有 `/post/:slug`，旧外链迁移后会直接失效或 404。

2. 分类与标签“点击后进入 slug 详情”链路不完整（高优先级）

- 当前只有 `/categories`、`/tags` 列表页，没有 `/categories/:slug`、`/tags/:slug` 详情/筛选路由。
- 分类页卡片和标签页标签是静态展示，未提供跳转动作。

3. 首页分类入口存在“有链接无落地”的问题（高优先级）

- 首页分类条跳转到 `/categories?slug=xxx`，但分类页未读取该参数并执行过滤。
- 用户点击后看不到“按分类筛选结果”，交互预期被打断。

4. 侧栏分类/标签缺少可导航交互（中优先级）

- 侧栏当前为纯文本 pill，不可点击。
- 与旧站“分类/标签可作为内容探索入口”的模式不一致。

5. 前后端筛选能力未贯通（中优先级）

- 前端文章查询仅支持 `keyword/page/pageSize/status`，后端公共列表接口也未支持 `categorySlug/tagSlug` 条件。
- 即使前端加了详情路由，也无法高效获取“某分类/某标签下文章列表”。

## 4. 交互功能补充计划

### 阶段 P0（先补齐用户主链路）

目标：让“分类/标签点击可筛选、旧站核心导航可达”先成立。

1. 前端路由补齐

- 新增 `categories/:slug`、`tags/:slug` 路由。
- 保留 `categories?slug=` 兼容解析，避免首页现有链接失效。
- 给分类卡片、标签项、侧栏 pill 增加可点击跳转。

2. 前端页面交互补齐

- 分类详情页：展示当前分类标题 + 对应文章列表。
- 标签详情页：展示当前标签标题 + 对应文章列表。
- 空态/加载态文案统一，提供返回全部分类/标签入口。

3. 后端查询能力补齐

- `ArticleQueryDto` 增加 `categorySlug`、`tagSlug`。
- `articles/public` 查询增加分类/标签过滤条件（支持组合筛选）。

验收标准：

- 点击任意分类/标签入口，URL 与内容筛选结果一致。
- 首页分类条点击后能直接看到对应分类文章，而不是全量分类列表。

### 阶段 P1（补旧站链接兼容）

目标：降低旧链接迁移成本，避免 SEO 与外链流量损失。

1. 路由兼容与重定向

- 增加 `/my-blog` 前缀兼容路由，并重定向到新路由。
- 增加 `/:year/:month/:day/:slug`（含 `/my-blog/...` 变体）兼容入口，规范化跳转到 `/post/:slug`。

2. 容错策略

- slug 无法匹配时跳转到 404，并给出“可能文章已迁移或下线”提示。
- 保留 query 参数，避免搜索来源参数丢失。

验收标准：

- 旧文章链接打开后可自动进入新详情页。
- 旧导航链接（含 `/my-blog/archives` 等）不会 404。

### 阶段 P2（体验收口与质量保障）

目标：让交互行为稳定、可维护、可回归。

1. 交互一致性

- Header、分类条、侧栏、详情页内分类/标签入口统一点击行为。
- 当前筛选项增加激活态，避免用户迷失。

2. 测试与回归

- 增加前台路由交互测试（最少覆盖：首页->详情、分类筛选、标签筛选、旧链接重定向）。
- 增加接口筛选参数测试，确保 `categorySlug/tagSlug` 生效。

3. 数据与运营

- 校验分类/标签 slug 唯一性与历史 slug 变更策略（必要时加别名表）。

验收标准：

- 路由/筛选主流程有自动化测试兜底。
- 旧站核心入口全部可用，且用户能通过分类/标签完成内容探索。

## 5. 建议实施顺序

1. 先做 P0（功能闭环），确保新站“分类/标签可探索”成立。
2. 再做 P1（兼容旧链接），处理历史流量与 SEO 风险。
3. 最后做 P2（测试和体验收口），降低后续回归成本。
