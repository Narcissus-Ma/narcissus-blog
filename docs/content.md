# 博客内容区域对齐落地方案

## 1. 项目现状分析

### 当前项目（narcissus-blog）
- **技术栈**：React + TypeScript + Vite
- **内容结构**：
  - HeroBanner（特色文章展示）
  - CategoryBar（分类栏）
  - 左侧文章列表（PostCard 组件）
  - 右侧 SidebarPanel（侧边栏）
  - 分页控件
- **优势**：现代化技术栈，组件化架构，响应式设计
- **不足**：文章卡片信息不够丰富，缺少摘要、评论数、日期等信息

### 旧博客项目（hexo-theme-anzhiyu）
- **技术栈**：Hexo + Pug + Stylus
- **内容结构**：
  - 分类组展示
  - 文章列表（包含丰富信息）
  - 每3篇文章插入广告位
  - 分页控件
- **优势**：丰富的文章卡片信息，良好的用户体验
- **不足**：技术栈相对老旧

## 2. 对齐目标

### 功能对齐
1. **文章卡片增强**：
   - 添加文章摘要
   - 显示评论数
   - 显示文章日期（创建/更新）
   - 添加置顶文章标记
   - 添加新文章标记
   - 添加未读文章标记

2. **布局优化**：
   - 实现文章封面位置交替（左右布局）
   - 增强文章卡片的悬停效果

3. **功能完善**：
   - 添加广告插入功能

### 技术实现
- 保持当前项目的现代化技术栈
- 基于现有组件进行增强
- 确保响应式设计

## 3. 具体实现步骤

### 步骤 1：增强 PostCard 组件

**文件**：`/apps/client/src/components/molecules/post-card/post-card.tsx`

**修改内容**：
1. **添加 props**：
   - `isSticky`: boolean（是否置顶）
   - `isNew`: boolean（是否新文章）
   - `isUnread`: boolean（是否未读）
   - `commentCount`: number（评论数）
   - `summary`: string（文章摘要）

2. **增强 UI**：
   - 添加置顶标记（图钉图标）
   - 添加新文章标记
   - 添加未读文章标记
   - 添加评论数显示
   - 添加文章日期显示
   - 添加文章摘要显示

3. **添加样式**：
   - 增强悬停效果
   - 添加标记样式

### 步骤 2：实现封面位置交替布局

**文件**：`/apps/client/src/pages/home-page/home-page.tsx`

**修改内容**：
1. **添加索引跟踪**：
   - 在文章列表映射时添加索引
   - 根据索引奇偶性设置封面位置

2. **传递布局信息**：
   - 向 PostCard 组件传递 `coverPosition` 属性
   - 支持 'left' | 'right' | 'none' 三种位置

### 步骤 3：添加广告插入功能

**文件**：`/apps/client/src/pages/home-page/home-page.tsx`

**修改内容**：
1. **添加广告配置**：
   - 在 site-store 中添加广告配置
   - 支持开关控制和广告内容配置

2. **实现广告插入逻辑**：
   - 每3篇文章后插入广告位
   - 广告位使用专门的组件

### 步骤 4：增强 API 服务

**文件**：`/apps/client/src/features/articles/services/articles-service.ts`

**修改内容**：
1. **扩展文章数据**：
   - 添加评论数字段
   - 添加摘要字段
   - 添加新文章标记逻辑

2. **添加未读文章标记**：
   - 实现本地存储记录已读文章
   - 在服务层处理未读标记逻辑

### 步骤 5：优化 SidebarPanel 组件

**文件**：`/apps/client/src/components/organisms/sidebar-panel/sidebar-panel.tsx`

**修改内容**：
1. **增强分类展示**：
   - 显示分类文章数量
   - 添加分类排序

2. **添加热门文章**：
   - 基于评论数或浏览量排序

3. **添加最新评论**：
   - 显示最新的评论列表

## 4. 技术方案

### 状态管理
- 使用现有的 `site-store` 管理广告配置
- 使用本地存储记录已读文章

### 数据获取
- 扩展现有 API 接口，添加缺失的字段
- 对于本地逻辑（如未读标记），在客户端处理

### 样式实现
- 使用 CSS Modules 保持样式隔离
- 添加适当的动画和过渡效果

### 响应式设计
- 保持现有的响应式布局
- 确保在移动设备上的良好体验

## 8. 风险评估

### 潜在风险
- API 接口扩展可能需要后端配合
- 广告插入可能影响页面加载性能
- 未读标记逻辑可能增加客户端存储压力

### 应对措施
- 与后端团队协调 API 扩展
- 实现广告的懒加载
- 定期清理本地存储的已读记录

## 9. 结论

通过本方案的实施，当前博客项目将在保持现代化技术架构的同时，实现与旧博客项目的功能对齐，为用户提供更加丰富和友好的内容浏览体验。

实施过程中应注重代码质量和用户体验，确保每一步修改都经过充分测试，以达到最佳的实现效果。
